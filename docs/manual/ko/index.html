1. 소개

한워드는 브라우저에서 쓰는 한국어 워드프로세서입니다. 문서 자체가 하나의 완결된 표준 HTML이고(그림은 data URI로 내장), 편집 방식과 단축키는 아래한글(HWP)을 따릅니다. 한글(HWPX), 워드(DOCX), HTML, 텍스트(TXT) 형식으로 열고 저장할 수 있고, 같은 코어를 쓰는 명령줄 도구(hanword)로 브라우저 없이 변환·검사도 할 수 있습니다.

  • 핵심은 Python 3.10 이상 표준 라이브러리만으로 동작합니다. 별도 패키지를 설치할 필요가 없습니다.
  • 기본은 내 컴퓨터에서만 접속되는 로컬 모드(127.0.0.1)입니다. 인터넷에 올리는 용도의 공개 변환기 모드(WP_PUBLIC=1)도 있습니다.
  • 저장소: github.com/gsungmoon-sketch/hanword · 라이선스 MIT.
모드문서가 저장되는 곳용도
로컬(기본)서버 컴퓨터의 문서 폴더내 PC 또는 믿을 수 있는 소규모 LAN
공개 변환기(WP_PUBLIC=1)저장 안 함(브라우저 올리기/내려받기만)HTTPS 리버스 프록시 뒤에서 인터넷 공개

2. 설치

2.1 내려받기와 SHA256 확인

릴리스(GitHub Releases)의 파일 중 내 환경에 맞는 것을 받습니다.

파일대상
hanword-<버전>-windows-x64-setup.exeWindows 64비트 설치 프로그램
hanword-<버전>-macos-arm64.pkgmacOS (Apple 실리콘)
hanword-<버전>-macos-x64.pkgmacOS (Intel)
hanword-<버전>-linux-x64.tar.gzLinux x86-64 (systemd)
hanword-<버전>.pyz어디서나(Python 3.10+ 필요)
SHA256SUMS위 파일들의 체크섬

받은 파일이 손상·변조되지 않았는지 확인하세요.

# Linux (받은 파일과 SHA256SUMS를 같은 폴더에)
sha256sum -c SHA256SUMS --ignore-missing
# macOS
shasum -a 256 hanword-0.1.9-macos-arm64.pkg
# Windows (PowerShell 또는 명령 프롬프트)
Get-FileHash .\hanword-0.1.9-windows-x64-setup.exe -Algorithm SHA256
certutil -hashfile hanword-0.1.9-windows-x64-setup.exe SHA256

출력된 값이 SHA256SUMS의 해당 줄과 같아야 합니다.

2.2 Windows

  1. setup.exe를 실행합니다(관리자 권한 필요).
  2. 서명되지 않은 파일이라 SmartScreen이 막을 수 있습니다. 추가 정보 → 실행을 누르세요.
  3. 설치 위치는 C:\Program Files\hanword\, Windows 서비스 hanword(WinSW)가 등록되어 127.0.0.1:8088에서 자동 시작합니다.
  4. 문서 폴더는 %ProgramData%\hanword\documents입니다.
  5. 시작 메뉴의 hanword 열기를 누르면 브라우저가 열립니다.
  6. 삭제: 설정 → 앱에서 제거합니다. 문서 데이터는 선택하지 않으면 남습니다(무인 설치 삭제 시 /PURGEDATA로 데이터까지 삭제).

2.3 macOS

  1. pkg를 엽니다. 서명·공증이 없을 수 있으니 막히면 pkg를 오른쪽 클릭 → 열기, 또는 시스템 설정 › 개인정보 보호 및 보안에서 “그래도 열기”를 누릅니다.
  2. 설치 위치: /usr/local/hanword, 명령 /usr/local/bin/hanword, LaunchDaemon com.hanword.server(자동 시작).
  3. 데이터: /Library/Application Support/hanword · 로그: /Library/Logs/hanword.
  4. 삭제: sudo /usr/local/hanword/uninstall.sh [--purge] (--purge=데이터까지 삭제)

2.4 Linux (systemd)

tar xzf hanword-0.1.9-linux-x64.tar.gz
cd hanword-0.1.9-linux-x64
sudo ./install.sh [--port N]
  • 설치 위치 /opt/hanword, 명령 /usr/local/bin/hanword, 데이터 /var/lib/hanword(사용자 hanword), 유닛 hanword.service.
  • 상태: systemctl status hanword · 로그: journalctl -u hanword
  • 삭제: sudo /opt/hanword/uninstall.sh [--purge]

2.5 어느 OS에서나: .pyz 또는 소스

# 단일 파일(.pyz)
python hanword-0.1.9.pyz serve

# 소스 받아서 실행
git clone https://github.com/gsungmoon-sketch/hanword
cd hanword
python server.py --host 127.0.0.1 --port 8088 --data ~/hanword-documents
python hanword convert in.docx out.hwpx   # CLI

설치형(패키지)에서는 명령이 하나(hanword)입니다: hanword serve [--host] [--port] [--data], hanword --version, 그리고 모든 CLI 하위 명령. 소스에서는 서버가 server.py, CLI가 hanword 스크립트입니다.

2.6 선택 구성요소(번들되지 않음)

없어도 핵심 기능은 동작합니다. 필요할 때 직접 설치하세요.

구성요소용도설치
pyhwp (AGPL-3.0).hwp(HWP5) 열기pip install pyhwp. PATH에 없으면 WP_HWP5_BIN에 bin 폴더 지정
python-hwpx + lxml대체 HWPX 엔진pip install python-hwpx lxml, WP_HWPX_ENGINE=pyhwpx
cryptography암호로 잠근 편집 역사pip install cryptography
poppler-utilsPDF 열기(pdftotext, pdftoppm)OS 패키지 관리자
ImageMagick서버의 래스터 PDF 조립OS 패키지 관리자
node + playwright벡터(글자가 살아 있는) PDFWP_PDF_LOCAL=1 WP_HTMLPDF=경로/htmlpdf.js WP_NODE_PATH=…

브라우저 인쇄와 “PDF로 저장”은 위 구성요소 없이도 됩니다(브라우저 인쇄 창, 그리고 내장된 html2canvas+jsPDF로 만드는 이미지형 PDF).

3. 처음 실행

  1. 설치형: 서비스가 이미 실행 중입니다. 브라우저에서 http://127.0.0.1:8088/을 엽니다(Windows는 시작 메뉴의 “hanword 열기”). 소스/.pyz는 먼저 서버를 실행하세요.
  2. 빈 문서가 나타나면 바로 입력합니다. 상단에 메뉴(파일·편집·보기·입력·서식·쪽·도구)와 도구모음이 있습니다.
  3. Alt+S로 저장하면 문서 폴더에 이름.html로 저장됩니다.
  4. 다른 형식이 필요하면 파일 메뉴의 “한글 문서로 저장 (HWPX)”, “PDF 저장” 등을 씁니다.
알아 두기접속 주소는 127.0.0.1 또는 localhost로 입력하세요. 다른 이름으로 접속하면 421 오류가 납니다(7장 참고). 포트가 이미 쓰이고 있으면 --port로 바꿉니다.

4. 편집기 사용법

메뉴는 로컬 모드 기준입니다. 공개 변환기 모드에서는 파일 메뉴가 “내 PC에서 열기(업로드)”, “…로 내려받기”로 바뀌고(HTML·HWPX·DOCX·TXT·PDF), 서버에는 아무것도 저장되지 않습니다. 단축키는 아래한글 표준을 따릅니다.

4.1 메뉴와 단축키

4.2 글자와 문단

글자 모양은 도구모음 또는 글자 모양 대화상자(Alt+L)에서 정합니다: 글꼴, 크기, 글자색, 음영색, 진하게·기울임·밑줄·취소선, 위첨자(Alt+Shift+P)·아래첨자(Alt+Shift+S). 문단 모양(Alt+T)에서 정렬·들여쓰기 등을 정합니다. 제목(h1~h3)과 목록(글머리표/번호, 9단계 수준)은 스타일(F6)과 목록 속성에서 지정합니다.

4.3 표

입력 → 표로 만듭니다. 셀 안에서 F5를 눌러 블록을 잡고 방향키로 범위를 넓히면 병합·나눔·테두리·배경을 한꺼번에 바꿀 수 있습니다.

기능조작
셀 블록F5 → 방향키
병합 / 나눔블록 상태에서 M / S
테두리 / 배경블록 상태에서 L / C

표 배치는 글자처럼 · 문단(어울림) · 고정 세 가지입니다. 어울림은 끌면 좌/우가 자동 전환되고 글이 표를 피해 흐릅니다. 표를 위아래로 나누기(표−)·붙이기(표+)도 됩니다.

4.4 그림과 도형

  • 그림(입력 → 그림): 하나의 개체 블록이 됩니다. 모서리·변 손잡이로 가로·세로 크기를 따로 조절하고, 네 변을 잘라내는 자르기, 회전·반전, 어울림 배치, 캡션(번호와 설명)을 쓸 수 있습니다. 그림은 문서 안에 내장됩니다.
  • 도형: 도구모음의 도형▾에서 사각형·원·선을 고릅니다. 선은 양 끝점을 끌어 수평·수직·대각선을 만들며 각도가 자동 스냅됩니다. 채우기색·선색·두께·실선/파선/점선을 바꾸고, 묶기·맞춤·배분, 겹침 순서(앞/뒤)를 지정합니다.

4.5 미디어와 쪽 배경

  • 입력 → 미디어 삽입(영상·소리): 문서 안에서 재생되는 영상을 넣습니다. 영상을 클릭하면 재생/일시정지, 컨트롤바로 구간·음량을 조절합니다. 공개 변환기 모드에서는 고른 파일을 이 브라우저 안에만 저장합니다. 로컬 모드의 삽입용 미디어는 문서 폴더의 media/에 있습니다.
  • 쪽 배경색: 편집 용지에서 색 견본을 골라 모든 쪽에 입힙니다.
  • 그림을 쪽 배경으로 지정하는 기능은 아직 계획 단계입니다(메뉴에 “계획중”으로 표시).

4.6 쪽 설정, 머리말·꼬리말, 목차, 미주

  • 편집 용지(F7): 용지 크기, 방향, 여백, 쪽 배경색.
  • 머리말/꼬리말, 쪽 번호 매기기: 쪽 메뉴. 쪽 나누기: Ctrl+Enter.
  • 목차 생성: 쪽 → 목차 생성. 현재 쪽번호 기준 목차를 1쪽 맨 앞에 만듭니다. 만든 뒤에는 일반 텍스트라 자유롭게 고칠 수 있고, 내용이 바뀌면 다시 생성해야 합니다(자동 갱신 없음).
  • 미주·캡션 번호: 넣고 지워도 번호가 자동으로 다시 매겨집니다. 필요하면 “미주 번호 갱신”, “캡션 번호 갱신”을 누릅니다.

4.7 찾기·바꾸기, 맞춤법, 글자 수

Ctrl+F(F2) 찾기, Ctrl+L 다음 찾기, Ctrl+H 찾아 바꾸기. F8 맞춤법 검사, 도구 → 글자 수.

4.8 되돌리기와 편집 역사

되돌리기는 무손실입니다. 되돌린 뒤 새로 편집해도 이전 흐름이 사라지지 않고, 계속 누르면 버렸던 가지까지 거슬러 올라갑니다. 도구 → 편집 역사 암호 설정/변경으로 암호를 지정하면 저장할 때 역사가 암호로 잠겨 문서와 함께 보존되고(cryptography 필요, 기본 꺼짐), 다시 열 때 암호를 넣으면 지난 세션 역사까지 이어서 되돌릴 수 있습니다. 암호는 어디에도 저장되지 않으므로 잃어버리면 역사만 복구할 수 없습니다(문서 본문은 무관).

4.9 인쇄와 PDF

  • PDF 저장(Alt+P) / 바로 인쇄(브라우저): 브라우저 인쇄 창을 쓰거나, 브라우저 안에서 이미지형 PDF를 만듭니다. 추가 구성요소가 필요 없습니다.
  • 벡터 PDF(글자가 선택·검색되는 PDF)는 서버 쪽 node+playwright 구성이 있을 때만 가능합니다(2.6절).
  • 프린터로 직접 인쇄하는 별도 장치용 기능은 이 공개판에 없습니다. 브라우저 인쇄를 사용하세요.

4.10 다른 형식으로 저장·열기

  • TXT 저장: 표는 상자 글자로 그려 메모장·터미널에서도 모양이 유지되고, 제목은 밑줄, 목록은 글머리표, 그림·영상·도형은 [그림]/[영상]/[도형]으로 표시됩니다. 쪽 나누기는 폼피드 문자로 남아 다시 열면 복원됩니다.
  • TXT 열기: UTF-8/CP949를 자동 판별해 문단으로 불러옵니다.
  • PDF 열기: “그대로”(쪽을 그림으로, 편집 불가·모양 유지) 또는 “글자만”(글자를 뽑아 문단으로, 편집 가능·배치 소실). 스캔본처럼 글자가 없는 PDF는 “글자만”이 거절되니 “그대로”를 쓰세요.

PDF (.pdf)글자 또는 쪽 그림예poppler-utils 필요(열기)

알려진 한계

  • 복잡한 HWPX 개체(차트 등), 변경 추적, 매크로는 지원하지 않습니다.
  • .doc는 텍스트만, .hwp는 pyhwp가 있어야 하며 HWP 3.x는 열 수 없습니다.
  • PDF 가져오기는 글자 또는 쪽 그림입니다.

크기·동시성 제한

  • CLI 입력 최대 200 MB, 서버 POST 본문 최대 64 MB.
  • PDF 래스터 최대 300쪽.
  • 동시 변환 수 WP_CONV_MAX(기본 2). 초과하면 HTTP 503(잠시 후 다시 시도).

왕복 검사

형식을 바꿔 저장했다가 다시 읽었을 때 내용이 손실되는지 확인하려면 hanword roundtrip 파일 --via hwpx|docx|html을 씁니다(손실이 있으면 종료 코드 1).

7. 문제 해결

증상원인과 해결
포트가 이미 사용 중이라 시작되지 않음--port(또는 WP_PORT)로 다른 포트를 지정.
접속하면 421 MisdirectedHost 헤더 검사(DNS 리바인딩 방어) 때문입니다. 127.0.0.1/localhost로 접속하거나, LAN에서 쓰는 이름을 WP_ALLOWED_HOSTS에 추가.
“listen 거부” 같은 메시지로 시작 안 됨바인드 정책입니다. 127.0.0.1이 아닌 주소는 WP_PUBLIC=1 또는 WP_ALLOW_REMOTE=1일 때만 허용(8장).
503 (바쁨)동시 변환 한도 초과. 잠시 후 재시도하거나 WP_CONV_MAX를 늘립니다.
글꼴이 다르게 보임해당 글꼴이 없어 번들 글꼴로 대체됨. 함초롬/은바탕은 번들되지 않습니다(10장 글꼴).
.hwp를 열 수 없음pip install pyhwp 후 필요하면 WP_HWP5_BIN 지정.
편집 역사 암호 오류암호가 틀렸거나 cryptography가 없음. 암호는 복구할 수 없습니다.
PDF를 못 엶poppler-utils(pdftotext, pdftoppm) 설치 확인.
Windows SmartScreen / macOS Gatekeeper서명되지 않은 파일입니다. 2.2, 2.3절 참고.
설정을 바꿨는데 반영 안 됨서비스를 재시작해야 합니다(10장 서비스 설정).

로그 위치: Linux journalctl -u hanword · macOS /Library/Logs/hanword · Windows 서비스 폴더 C:\Program Files\hanword\의 WinSW 로그 · 직접 실행은 터미널 출력.

8. 보안

로컬 모드에는 로그인이 없습니다포트에 접근할 수 있는 사람은 누구나 문서를 읽고 쓰고 지울 수 있습니다. 그래서 기본은 127.0.0.1에만 바인드하며, 다른 주소는 WP_PUBLIC=1 또는 WP_ALLOW_REMOTE=1 없이는 거부됩니다. WP_ALLOW_REMOTE=1은 믿을 수 있는 LAN에서만 쓰세요.
  • Host 헤더 검사(DNS 리바인딩 방어, 불일치 시 421), 교차 출처 POST 차단(403).
  • 요청마다 nonce가 붙는 CSP, X-Frame-Options DENY, nosniff, no-referrer.
  • 업로드 크기 제한, HWPX/DOCX의 zip 폭탄·XXE에 안전한 파싱(expat, 엔티티 검사), 링크 스킴 화이트리스트.
  • WP_DEBUG=1은 로컬 디버그 브리지를 엽니다. 공유 컴퓨터에서는 절대 켜지 마세요.

인터넷에 공개하려면

WP_PUBLIC=1(저장 없는 변환기 모드)로 실행하고, HTTPS 리버스 프록시 뒤에 두며, WP_PUBLIC_HOST에 내 도메인을 지정하세요. 로컬 모드를 그대로 인터넷에 열면 안 됩니다.

# 한워드: 127.0.0.1에서 공개 모드 실행
WP_PUBLIC=1 WP_PUBLIC_HOST=docs.example.com WP_SITE_URL=https://docs.example.com hanword serve --port 8088

# Caddy
docs.example.com {
    reverse_proxy 127.0.0.1:8088
}

# nginx (server 블록 안, TLS 인증서 설정은 별도)
location / {
    proxy_pass http://127.0.0.1:8088;
    proxy_set_header Host $host;
    client_max_body_size 64m;
}

취약점은 GitHub Security Advisories로 알려 주세요(저장소의 SECURITY.md 참고).

9. CLI 참고

브라우저 없이 같은 코어를 씁니다. 패키지 설치 시 hanword, 소스에서는 python hanword. 전역 옵션 --json은 기계가 읽기 좋은 JSON 출력을 냅니다. 파일 자리에 -를 쓰면 표준 입력/출력입니다. 입력은 최대 200 MB.

명령설명
formats읽기/쓰기 가능한 형식 목록
convert IN OUT [--from F] [--to F] [--paper A4] [--orient portrait|landscape] [--pdf-mode text|image]형식 변환. 형식은 확장자로 추정하며 --from/--to로 지정 가능
info FILE문서 요약 정보
check FILE파싱과 검증. 오류가 있으면 종료 코드 1
roundtrip FILE [--via hwpx|docx|html]왕복 변환 후 손실 검사. 손실이 있으면 1
model FILE|-문서 모델(JSON) 출력(--json이면 한 줄)
render MODEL.json|- OUT|-모델을 편집기 HTML로(OUT 확장자가 .docx/.hwpx/.txt/.pdf면 그 형식)
apply MODEL|- OPS.json|- [-o OUT]편집 연산을 적용해 새 모델 JSON 출력. MODEL은 .json 또는 문서
debug state|log|snapshot|eval JS|cmd OP [--arg A] [--port 8088]로컬 디버그 서버 전용(WP_DEBUG=1). 꺼져 있으면 종료 코드 3
serve, --version(설치형) 서버 실행 / 버전 출력

종료 코드

코드뜻
0성공
1검사(check)·왕복(roundtrip)에서 결함 발견
2사용법 또는 입력 오류
3디버그 비활성

예

hanword formats
hanword convert report.docx report.hwpx
hanword convert notes.txt notes.pdf --paper A4 --orient landscape
hanword convert scan.pdf scan.html --pdf-mode image
hanword info report.hwpx
hanword --json check report.hwpx; echo $?
hanword roundtrip report.docx --via hwpx
hanword model report.docx > report.model.json
hanword render report.model.json out.html
cat report.docx | hanword convert - out.hwpx --from docx

apply: 편집 연산

위치는 [블록 번호, 글자 오프셋](0부터)입니다. 연산 목록은 순서대로 적용되며 하나라도 실패하면 전체가 실패하고(어느 연산인지 표시) 입력은 바뀌지 않습니다. 표·그림·쪽 나누기 같은 잠금 블록 안의 글은 보통 위치로는 편집할 수 없고, 표 칸 안 글은 글 연산(insert_text·delete_range·set_style·split_paragraph)에 칸 위치 [표 블록, 줄, 칸, 칸 문단, 오프셋]을 줍니다(줄·칸 = 격자 좌표, 병합 칸은 왼쪽 위, start·end는 같은 칸). 표 연산도 격자 좌표를 쓰며, 구조 연산은 짧은 줄 끝 빈 자리를 빈 칸으로 채운 뒤 동작하고 병합이 겹친 표는 거절합니다.

op인자
insert_textpos, text
delete_rangestart, end (start < end)
set_stylestart, end, attrs — bold/italic/underline/strike/sup/sub(true — sup·sub는 서로 끔), color/highlight(#RRGGBB), size(1~400), font, link. 값 null 또는 false는 해제
set_block_typeindex, type(p/h1/h2/h3/li/div), 선택: list(bullet|number), level(li만), align, indent
split_paragraphpos
merge_paragraphindex (index 블록과 다음 블록 병합)
insert_pgbreakpos
delete_blockindex
insert_blockindex, block
insert_tablepos, rows(1~200), cols(1~64) — pos에서 문단을 나눔
table_insert_rows / table_delete_rowsindex, at, n(넣기 n ≤ 100) — 병합 칸 안쪽에 넣으면 rowspan 늘림, 지우면 줄임(첫 줄이 지워진 병합 칸은 글 유지), 마지막 줄 지우기는 거절(delete_block)
table_insert_cols / table_delete_colsindex, at, n — colspan 같은 규칙. 칸 너비가 있으면 새 칸 = 이웃 평균, 표 너비 유지(비례 조정)
table_mergeindex, r0, c0, r1, c1(격자, 포함) — 직사각형만(밖으로 걸친 병합 = 거절). 글 = 빈 칸 빼고 칸 순서대로 문단 이어 붙임, 서식 = 첫 칸
table_splitindex, r, c — 합친 칸을 1×1 칸들로(글은 첫 칸)
table_cellindex, r, c, 선택: runs | paras([{runs, align?}]), bg(#RRGGBB, "" = 지움), align("" = 지움)
insert_imagepos, src(data:image/png|jpeg|gif|webp|bmp;base64), 선택 width(1~5000) — 그림 블록(글자처럼). 지우기 = delete_block
set_imageindex(그림 블록) 또는 pos(글자처럼 그림 run·그림 블록), width(1~5000) — 위치 값 그대로
set_page선택: paper, orient(portrait|landscape), margins("위,오른,아래,왼" mm) — "" = 지움
